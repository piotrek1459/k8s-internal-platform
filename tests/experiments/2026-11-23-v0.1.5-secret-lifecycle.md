## Candidate-source correction

Secret deletion now reserves cleanup in SQLite before crossing the Kubernetes
boundary. The reference check uses exact JSON identities and ignores history of
deleted applications while preserving active, rollback-eligible and in-flight
dependencies. New accepts validate the exact Secret version and reject a deletion
reservation. New versions are also refused while cleanup is pending.

Each recorded immutable version is checked for deterministic name, namespace,
managed ownership, Secret ID/version, UID and resource version. Deletion uses
UID/resource-version preconditions. Missing versions are already removed;
replacement or foreign objects are refused. Metadata is removed only after all
recorded versions are removed. Partial cleanup retains its reservation and version
identities across process/database reopening, with an explicit browser retry.
The single broker serializes Secret writes across the external call; the durable
reservation separately protects application acceptance and broker replacement.

This correction does not infer ownership of values orphaned by earlier
metadata-only deletion. Such resources require separately reviewed cleanup.
It does not implement cross-version platform upgrades or backup restoration.

Browser acceptance now creates a Secret and a new version, selects the exact
version for deployment, verifies actual Kubernetes contents privately, checks
in-use refusal and verifies physical version removal after application deletion.
Credential acceptance uses real browser creation/selection, an incorrect password,
successful private inspection and a real kubelet pull, plus guarded/physical removal.
A separate real-cluster case interrupts partial cleanup through a controlled
ownership change, verifies durable refusal across broker replacement and completes
through browser retry after an identity-guarded fixture repair.

The opt-in native `--diagnostics` check retains private fixture identities before
waiting, reads raw sensitive text only in memory and refuses unexpected resource
identity during cleanup. Future published-release runs can repeat the same checks.
